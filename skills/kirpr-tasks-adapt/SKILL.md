# Адаптация декомпозиции

Ты — архитектор-адаптор. Твоя задача — обновить существующую декомпозицию задачи на основе новых вводных, не пересоздавая её с нуля.

## Инициализация

1. Прочитай файл `~/.local/share/kirpr/config/templates.md` — там шаблоны, чеклисты, правила и паттерн загрузки контекста.
2. Номер задачи: аргументы явного вызова (например `SAS-200`).
3. Найди директорию задачи (lowercase номер задачи).
4. Если директория не найдена — **прерви выполнение**: "Декомпозиция для {номер} не найдена. Запустите `$kirpr-tasks-decompose` в Codex или `/kirpr:tasks-decompose` в Claude Code."

## Загрузка контекста

Следуй паттерну загрузки из `~/.local/share/kirpr/config/templates.md` (секция «Загрузка контекста декомпозиции»).

После загрузки базового контекста:
- **Не читай все подзадачи сразу** — читай их по мере необходимости, когда станет понятно какие затронуты.

## Выполнение

### Фаза A: Сбор новых вводных

1. Покажи пользователю краткое резюме текущей декомпозиции (из `.context.md` секция 0 TL;DR или из `00-overview.md`):
   - Кол-во задач, суммарные часы
   - Список фаз
   - Дата последней декомпозиции/адаптации
2. Спроси: **"Что изменилось? Выберите или опишите:"**
   1. Обновилось описание задачи в трекере (перезагружу данные)
   2. Изменились требования (опишите что именно)
   3. Нужно добавить/удалить/переоценить подзадачи
   4. Изменились зависимости или порядок
   5. Другое (опишите)
3. Если пользователь выбрал (1) — выполни **частичный re-fetch**:
   - Прочитай `~/.local/share/kirpr/config/tracker-runtime.md` и строго выполни его инструкцию выбора runtime для операции fetch. Она читает `~/.config/kirpr/tracker.md` и определяет скрипт трекера. Выполни выбранный скрипт.
   - Сравни с данными из `.context.md` секция 1.
   - Покажи diff: что изменилось в summary, description, comments.

### Фаза B: Анализ влияния

1. На основе новых вводных определи **зону влияния** — какие файлы затронуты:
   - `обновить` — нужно обновить содержимое
   - `без изменений` — оставить как есть
   - `новый` — нужно создать
   - `удалить` — подзадача больше не нужна
2. Покажи пользователю таблицу влияния:
   ```
   Анализ влияния:
   [обновить]        03-1-feed-listing.md — изменились требования для фильтрации
   [обновить]        00-overview.md — обновить граф зависимостей
   [новый]           03-4-caching.md — добавлена задача на кэширование
   [удалить]         03-3-actions.md — объединена с 03-2
   [без изменений]   01-schema.md, 02-1-domain-model.md, ...
   ```
3. Спроси подтверждение: "Согласны с зоной влияния? Или нужно добавить/исключить файлы?"

### Фаза C: Дискуссия по изменениям (цикл)

1. **Прочитай только затронутые файлы** (`обновить` + те, от которых зависят `новый` файлы).
2. Для каждого затронутого файла предложи конкретные изменения.
3. Задавай уточняющие вопросы **по одному**, с вариантами.
4. После каждого ответа — покажи обновлённый план изменений.
5. Цикл завершается когда пользователь говорит "применяй" / "готово".

### Фаза D: Верификация изменений

Проверь чеклист из `~/.local/share/kirpr/config/templates.md` (секция «Чеклист верификации»), но **только для затронутых подзадач и их зависимостей.**

Если не пройден — вернись к Фазе C.

### Фаза E: Применение изменений

1. Покажи **итоговый diff** перед записью:
   ```
   Изменения к применению:

   [ОБНОВИТЬ] 03-1-feed-listing.md
     - Секция 2: добавлен фильтр по severity
     - Оценка: 3ч → 4ч

   [ОБНОВИТЬ] 00-overview.md
     - Граф: добавлена связь 3.1 → 3.4
     - Итого: 21ч → 25ч

   [СОЗДАТЬ] 03-4-caching.md
     - Задача 3.4 — Redis кэш для Feed [apisrv, ~3ч]

   [УДАЛИТЬ] 03-3-actions.md
     - Объединена с 03-2-issue-detail.md
   ```
2. Дождись подтверждения пользователя.
3. Запиши изменения:
   - Обнови затронутые файлы.
   - Создай новые файлы по шаблону из `~/.local/share/kirpr/config/templates.md`.
   - Удали файлы, помеченные как `удалить`.
   - Обнови `00-overview.md` (граф, карта файлов, итоги).
4. Обнови `.context.md`:
   - Секция 3: добавь новые решения.
   - Секция 4: обнови структуру.
   - Секция 5: обнови карту файлов (статусы: `generated` → `modified`, `new`, `removed`).
   - Секция 7: обнови дату адаптации, инкрементируй счётчик адаптаций.
5. Покажи итоги: какие файлы обновлены, созданы, удалены.

## Обработка конфликтов

Если файл был изменён вручную (дата модификации файла позже даты из `.context.md` секция 7):
1. Прочитай текущее содержимое файла.
2. Покажи пользователю: "Файл `{имя}` был изменён вручную после декомпозиции. Как поступить?"
   1. Сохранить ручные изменения и адаптировать поверх
   2. Перезаписать файл с нуля
   3. Пропустить этот файл

## Дополнительные правила adapt

- **Не перезаписывай всё.** Обновляй только затронутые файлы.
- **Если `.context.md` повреждён или неполон** — сообщи пользователю и предложи: (1) восстановить из файлов, (2) «Запустите `$kirpr-tasks-decompose` в Codex или `/kirpr:tasks-decompose` в Claude Code.»
- **Если скрипт fetch вернул ошибку при re-fetch** — продолжай с кэшированными данными, сообщи пользователю.
