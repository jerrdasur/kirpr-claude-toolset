# Workflow декомпозиции: фазы

## Фаза 1: Fetch данных из трекера

1. Прочитай `~/.local/share/kirpr/config/tracker-runtime.md` и строго выполни его инструкцию выбора runtime для операции fetch. Она читает `~/.config/kirpr/tracker.md` и определяет скрипт для текущего трекера задач.
2. Выполни выбранный скрипт с номером задачи — он загрузит данные и выведет готовый markdown (summary, description, comments).
3. Если скрипт вернул ошибку — **прерви выполнение**, сообщи пользователю.
4. Из описания и комментариев извлеки номера связанных задач. Для каждой связанной задачи выполни скрипт повторно (до 50 штук).
5. Создай директорию для задачи (lowercase номер задачи, например `sas-200/`).
6. Создай `source.md` по шаблону из `~/.local/share/kirpr/config/templates.md`.

## Фаза 2: Интерактивный анализ контекста

**2a — Первичный обзор:**
Покажи пользователю:
- Название и описание задачи из трекера
- Список связанных задач (если найдены)
- Какие существующие декомпозиции найдены в репо

**2b — Вопросы по контексту (цикл, по одному):**
Задавай вопросы по одному, предлагая варианты где возможно. Примеры вопросов:
- Какие модули/сервисы затрагивает задача? (варианты на основе данных из трекера)
- Нужно ли исследовать конкретные директории в кодовой базе?
- Есть ли архитектурные документы, ADR или гайдлайны, которые нужно учитывать?
- Есть ли зависимости от других команд или внешних систем?
- Какие конвенции по тестированию, миграциям, код-ревью нужно учесть?
- Есть ли ограничения по срокам или приоритетам?

Не задавай все вопросы сразу — адаптируй следующий вопрос к ответу на предыдущий. Прекрати задавать вопросы, когда пользователь скажет что контекст собран или когда ты считаешь, что собрал достаточно информации для драфта.

**2c — Исследование кодовой базы:**
На основе ответов пользователя исследуй указанные директории, файлы, паттерны в кодовой базе. Покажи пользователю ключевые находки и спроси, правильно ли понят контекст.

**2d — Формирование первого драфта:**
Сформируй первичный драфт декомпозиции:
- Список фаз (группировка подзадач)
- Список подзадач с названиями и примерными оценками
- Предварительный граф зависимостей
- Предварительные параллельные потоки

Представь драфт пользователю и перейди к Фазе 3.

## Фаза 3: Дискуссия по декомпозиции (цикл)

1. Представь текущий драфт декомпозиции.
2. Задавай уточняющие вопросы **по одной**, предлагая варианты:
   - Подзадача X выглядит крупной (~6ч). Разбить на X.1 и X.2?
   - Нужна ли отдельная задача на тесты для фазы Y?
   - В каком порядке должны идти задачи Z и W?
   - Пропущена ли задача на миграции/документацию/интеграцию?
3. После каждого ответа — обнови драфт и покажи изменения.
4. Цикл завершается когда:
   - Пользователь говорит "финализируй" / "готово" / "ок"
   - **ИЛИ** ты считаешь что декомпозиция готова — тогда предложи завершить, объяснив почему

## Фаза 4: Верификация по чеклисту

Перед генерацией файлов проверь каждый пункт и покажи результат пользователю:

```
Чеклист завершённости:
[ ] Все подзадачи <= 4 часов
[ ] Граф зависимостей непротиворечив и полон
[ ] Критерии готовности определены для каждой подзадачи
[ ] Параллельные потоки идентифицированы
[ ] Тесты учтены (отдельные задачи или внутри подзадач)
[ ] Миграции и документация не пропущены
[ ] Оценка трудозатрат есть для каждой подзадачи
```

Если хотя бы один пункт не пройден — **вернись к Фазе 3** и предложи доработки.
Если все пройдены — спроси пользователя "Чеклист пройден. Генерирую файлы?" и жди подтверждения.

## Фаза 5: Генерация файлов

**Перед началом генерации** прочитай `~/.local/share/kirpr/config/style-examples.md` — там курированные примеры стиля, гранулярности и формата.

Создай файлы в директории задачи по шаблонам из `~/.local/share/kirpr/config/templates.md`:
1. `source.md` (если не создан в Фазе 1)
2. `00-overview.md` — навигационный индекс
3. `XX-Y-name.md` — по одному файлу на каждую подзадачу
4. **`.context.md`** — кэш контекста сессии. **Обязательный шаг** — без этого файла `$kirpr-tasks-adapt` и `$kirpr-tasks-review` в Codex или `/kirpr:tasks-adapt` и `/kirpr:tasks-review` в Claude Code не смогут использовать быстрый путь загрузки контекста.

После генерации:
- Покажи список созданных файлов и итоги (кол-во задач, суммарные часы).
- **Проверь что `.context.md` создан.** Если файл не создан — создай его перед завершением.
