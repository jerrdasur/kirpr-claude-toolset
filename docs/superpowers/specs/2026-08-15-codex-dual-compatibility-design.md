# kirpr — двойная совместимость с Claude Code и Codex

**Дата:** 2026-08-15  
**Статус:** дизайн утверждён

## Задача

Репозиторий поставляет 12 slash-команд и три скила для Claude Code. Команды,
общие ресурсы и установщики жёстко привязаны к `~/.claude`, а тексты промптов
ссылаются на синтаксис и возможности Claude Code. Нужно добавить полноценную
поддержку Codex, сохранить существующий интерфейс Claude Code и установить
результат на текущей машине.

Codex custom prompts не подходят как целевой формат: они deprecated. Нативной
единицей повторно используемого workflow является skill, который Codex загружает
из `$HOME/.agents/skills`. Поэтому каноническим форматом kirpr становятся skills,
а существующие Claude slash-команды остаются совместимыми обёртками.

Официальные основания:

- [Build skills](https://developers.openai.com/codex/skills) — структура skills,
  явный вызов, пользовательский каталог и поддержка symlink;
- [Custom prompts](https://developers.openai.com/codex/custom-prompts) — статус
  deprecated и рекомендация использовать skills.

## Цели

- Сохранить все существующие `/kirpr:*` в Claude Code.
- Добавить 12 отдельных Codex-skills с вызовом `$kirpr-*`.
- Установить `expert-panel`, `grill-me` и `kirpr-flow` нативно для обеих платформ.
- Держать поведение операций в одном каноническом месте.
- Разделить поставляемые ресурсы и изменяемые пользователем данные.
- Сделать установку, обновление, миграцию и удаление безопасными и
  идемпотентными.
- После автоматических проверок установить обе платформенные цели на текущей
  машине.

## Не цели

- Публикация kirpr в каталоге Codex plugins.
- Замена Markdown-конфигурации трекера другим пользовательским форматом.
- Изменение бизнес-поведения команд, контрактов Python-скриптов или форматов
  создаваемых задач.
- Массовое переписывание `.claude/*` во всех пользовательских репозиториях.
- Поддержка deprecated Codex custom prompts как отдельного интерфейса.

## Каноническая структура

Каждая существующая команда становится отдельным skill:

```text
skills/
  kirpr-task-fetch/
  kirpr-task-create/
  kirpr-task-update/
  kirpr-task-delete/
  kirpr-tasks-decompose/
  kirpr-tasks-review/
  kirpr-tasks-adapt/
  kirpr-tasks-push/
  kirpr-adr-init/
  kirpr-adr-write/
  kirpr-adr-review/
  kirpr-text/
  expert-panel/
  grill-me/
  kirpr-flow/
```

В каждом новом каталоге находятся:

- `SKILL.md` — единственный канонический workflow операции;
- `agents/openai.yaml` — метаданные Codex и
  `policy.allow_implicit_invocation: false`.

Все 15 skills устанавливаются и в Claude Code, и в Codex. Файлы
`commands/kirpr/*.md` больше не содержат workflow: каждый читает соответствующий
`~/.claude/skills/kirpr-*/SKILL.md` и передаёт ему `$ARGUMENTS`. Так сохраняется
старый синтаксис `/kirpr:*`, но поведение не дублируется.

## Карта вызовов

| Операция | Claude Code | Codex |
|---|---|---|
| Получить задачу | `/kirpr:task-fetch SAS-200` | `$kirpr-task-fetch SAS-200` |
| Создать задачу | `/kirpr:task-create SAS ...` | `$kirpr-task-create SAS ...` |
| Изменить задачу | `/kirpr:task-update SAS-200 ...` | `$kirpr-task-update SAS-200 ...` |
| Удалить задачу | `/kirpr:task-delete SAS-200` | `$kirpr-task-delete SAS-200` |
| Декомпозировать | `/kirpr:tasks-decompose SAS-200` | `$kirpr-tasks-decompose SAS-200` |
| Проверить декомпозицию | `/kirpr:tasks-review SAS-200` | `$kirpr-tasks-review SAS-200` |
| Адаптировать декомпозицию | `/kirpr:tasks-adapt SAS-200` | `$kirpr-tasks-adapt SAS-200` |
| Создать подзадачи | `/kirpr:tasks-push SAS-200` | `$kirpr-tasks-push SAS-200` |
| Инициализировать ADR | `/kirpr:adr-init` | `$kirpr-adr-init` |
| Написать ADR | `/kirpr:adr-write SAS-200` | `$kirpr-adr-write SAS-200` |
| Проверить ADR | `/kirpr:adr-review SAS-200` | `$kirpr-adr-review SAS-200` |
| Отредактировать текст | `/kirpr:text ...` | `$kirpr-text ...` |

`expert-panel`, `grill-me` и `kirpr-flow` сохраняют имена. В Codex они
вызываются через `$`, в Claude Code — существующим способом.

## Разделение файлов

### Поставляемые ресурсы

`~/.local/share/kirpr/` содержит файлы, которыми управляет установщик:

```text
config/     шаблоны, workflow, правила и рубрики
prompts/    системные промпты
scripts/    Python-скрипты трекеров
```

Skills обеих платформ ссылаются на один runtime-каталог. Обновление может
заменять эти файлы целиком.

### Пользовательские данные

`~/.config/kirpr/` содержит постоянные пользовательские данные и служебное
состояние установщика:

```text
tracker.md
custom-experts.md
install-manifest
backups/<timestamp>/...
```

`tracker.md` и `custom-experts.md` принадлежат пользователю и не
перезаписываются. `install-manifest` и `backups/` обслуживает установщик. Токены
не записываются в эти файлы: как и сейчас, они читаются из переменных окружения.

### Состояние проекта

Новые платформонезависимые пути:

- `.kirpr/grill-me/lenses.md`;
- `.kirpr/expert-panel-ignore`.

Состояние конкретных grill-me-сессий остаётся в выбранном пользователем каталоге
под `docs/`. Установщик не обходит рабочие репозитории и не меняет их файлы.

Если новый путь отсутствует, а legacy-файл `.claude/*` найден, skill предлагает
перенос. До решения пользователя legacy-файл можно читать, но нельзя менять.

## Аргументы и платформенные возможности

Канонический `SKILL.md` не использует `$ARGUMENTS`: он разбирает текст, переданный
при явном вызове. Claude-обёртка превращает `$ARGUMENTS` в явно обозначенный блок
аргументов для skill.

Промпты не называют конкретные инструменты Claude Code. Вместо этого они
описывают требуемую возможность: прочитать файл, спросить пользователя, запустить
команду или делегировать изолированному агенту.

Где делегирование служит только ускорением, допустим последовательный fallback с
явным уведомлением. Где свежий независимый агент является частью гарантии
workflow, отсутствие делегирования останавливает операцию с понятным сообщением.
Это относится прежде всего к агентному режиму `kirpr-flow execute` и независимым
голосам `expert-panel`.

Ссылки между операциями показывают оба синтаксиса вызова. Подтверждения перед
созданием, изменением и безвозвратным удалением задач сохраняются без ослабления.

## Конфигурация трекера

`tracker.md` остаётся человекочитаемым Markdown, но больше не содержит команду с
платформенным абсолютным путём. Он задаёт активный трекер, URL и имена требуемых
переменных окружения. Skill выбирает скрипт из
`~/.local/share/kirpr/scripts/` по значению активного трекера.

Миграция удаляет из семантики конфигурации старый путь
`~/.claude/kirpr/scripts/...`, не меняя выбранный трекер и URL.

## Установщик

### Интерфейс

```text
./install.sh [--target claude|codex|all]
./uninstall.sh [--target claude|codex|all]
```

Без `--target` в интерактивном терминале предлагаются Claude Code, Codex и обе
платформы. В non-interactive режиме отсутствие target является ошибкой с
примером корректного вызова.

Цели установки:

| Target | Skills | Совместимые команды |
|---|---|---|
| `claude` | `~/.claude/skills/<name>/` | `~/.claude/commands/kirpr/` |
| `codex` | `~/.agents/skills/<name>/` | нет |
| `all` | обе строки выше | Claude-команды |

Локальная установка копирует файлы. Режим симлинков не добавляется: он создаёт
другую семантику обновления и не нужен для поставленной задачи.

### Транзакция

1. Разобрать аргументы и определить target.
2. Собрать полный bundle во временном каталоге.
3. Проверить список файлов, front matter skills и доступность директорий.
4. Найти пользовательские данные и конфликты.
5. Сохранить вытесняемые одноимённые файлы в датированный backup.
6. Установить runtime, skills и Claude-обёртки.
7. Атомарно заменить manifest только после успешного копирования.
8. При ошибке восстановить предыдущее состояние из backup.

Установщик удаляет и заменяет только известные каталоги kirpr. Чужие skills и
соседние файлы не затрагиваются.

### Удалённая установка

`install-remote.sh` скачивает архив репозитория во временный каталог, проверяет
ожидаемую структуру и запускает находящийся в архиве `install.sh` с теми же
аргументами. Отдельного вручную поддерживаемого списка файлов больше нет.
Сетевой сбой не меняет текущую установку.

## Миграция

Для `tracker.md` и `custom-experts.md` действует приоритет:

1. `~/.config/kirpr/`;
2. legacy-данные `~/.claude/`;
3. импортированные данные `~/.agents/skills/`.

Если два источника содержат разные пользовательские данные, установка
останавливается до замены управляемых файлов и показывает конфликтующие пути.
Установщик не объединяет конфигурацию эвристически.

На текущей машине уже существуют автоматически импортированные `expert-panel`,
`grill-me` и `kirpr-flow`; у `grill-me` путь ошибочно преобразован в `.Codex`.
Также присутствуют отдельные Codex-native `kirpr-adr` и `kirpr-text`, поведение
которых расходится с репозиторием.

При первой установке:

- все вытесняемые версии сохраняются в backup;
- `kirpr-text` заменяется каноническим skill;
- агрегированный `kirpr-adr` удаляется из активного набора после backup, потому
  что его заменяют три явных ADR-skills;
- удачные платформонезависимые формулировки существующих Codex-skills можно
  использовать при адаптации, но они не меняют утверждённое поведение kirpr.

## Uninstall

`uninstall.sh` удаляет только пути из manifest для выбранного target. Runtime
удаляется лишь тогда, когда не остаётся установленной платформенной цели.
`~/.config/kirpr/` сохраняется по умолчанию; удаление пользовательских данных
требует отдельного подтверждения.

Если первая установка вытеснила существующие одноимённые skills, uninstall
предлагает восстановить записанный backup. Проектные `.kirpr/` и `.claude/`
никогда не удаляются.

## Ошибки и безопасность

- Неизвестный target, неполный bundle, недоступный backup-каталог и конфликт
  пользовательских данных завершают работу до замены файлов.
- Ошибка после начала копирования запускает rollback и не обновляет manifest.
- Логи не печатают значения токенов и содержимое конфигурации с секретами.
- `task-delete` сохраняет ручное подтверждение номером задачи; `да` не считается
  подтверждением.
- Операции записи в трекер сохраняют preview или diff до подтверждения.

## Тестирование

### Статические проверки

- У каждого skill валидный front matter, а `name` совпадает с каталогом.
- У всех новых Codex-skills задано
  `policy.allow_implicit_invocation: false`.
- В канонических skills нет `.Codex`, `~/.claude/kirpr`, `$ARGUMENTS` и имён
  Claude-only инструментов.
- Каждая Claude-обёртка ссылается на существующий skill и передаёт аргументы.

### Установщик

Тесты запускаются с временным `HOME` и покрывают:

- targets `claude`, `codex` и `all`;
- интерактивный выбор и ошибку non-interactive запуска без target;
- чистую и повторную установку;
- сохранение пользовательских данных;
- миграцию из каждого legacy-источника;
- остановку при конфликте;
- backup, rollback, uninstall и восстановление вытеснённых файлов;
- отсутствие изменений вне manifest.

Скрипты проходят `bash -n` и доступный shell linter. Python-скрипты проходят
существующий набор unit-тестов.

### Smoke-проверка

После установки `--target all` новая сессия Codex должна обнаружить все 15
skills. Проверка не вызывает операции записи в трекер. При наличии Claude Code
проверяется обнаружение старых `/kirpr:*` без внешних изменений.

## Критерии готовности

- Все 12 операций доступны как отдельные `$kirpr-*` и только по явному вызову.
- Три существующих skills работают из Codex без Claude-only путей.
- Старые `/kirpr:*` работают через тонкие обёртки.
- Обе платформы используют один runtime и одну пользовательскую конфигурацию.
- Повторная установка не меняет пользовательские данные.
- Конфликтующие текущие Codex-skills сохранены в backup.
- README описывает обе платформы, синтаксис вызова, установку, обновление и
  удаление.
- Все статические, shell, Python и smoke-проверки проходят.
- Обе цели установлены на текущей машине.
