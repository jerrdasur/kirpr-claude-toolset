# grill-me — прожарка продуктовых гипотез

**Дата:** 2026-08-12
**Статус:** дизайн утверждён

## Задача

В репозитории есть инструменты для того, что уже решено: декомпозиция задачи, ADR по принятому решению, ревью спеки панелью экспертов. Все они начинаются с момента, когда предмет сформулирован.

Нет инструмента для стадии до этого — когда есть продуктовая гипотеза, и неизвестно, выдержит ли она вопросы. `expert-panel` тут не помогает: он разбирает готовый артефакт и выдаёт отчёт с замечаниями. Гипотезу нельзя отревьюить — её надо допросить.

Нужен скил, который ведёт бесконечный допрос по предмету, находит в нём нестыковки, неоднозначности, неизвестные и усложнения, задаёт открытые вопросы и не останавливается, пока не сказано остановиться. На выходе — документ со всей собранной фактурой, написанный по правилам `kirpr:text`.

## Референс

`grilling` от Matt Pocock (`mattpocock/skills`), на который ссылается вирусный `/grill-me`. Оттуда взяты две идеи:

- **Дерево решений и фронтир.** Вопросы задаются только там, где предпосылки уже закрыты. Вопрос, ответ на который зависит от другого незакрытого вопроса, ждёт своей очереди.
- **Факты ищет агент, решения принимает человек.** Всё, что можно выяснить самому, скил выясняет сам и не тратит на это ход пользователя.

Четыре вещи сделаны иначе:

| | Pocock | Здесь |
|---|---|---|
| Предмет | план или дизайн системы | продуктовая гипотеза |
| Завершение | фронтир опустел | только прямая команда пользователя |
| Выход | общее понимание в диалоге | документ на диске через `kirpr:text` |
| Вопросы | весь фронтир одним сообщением, к каждому вопросу рекомендованный ответ агента | один открытый вопрос за раз, без гипотез агента |

Отказ от рекомендованных ответов принципиален. Для архитектурного решения подсказка агента экономит время: вариантов конечное число, и пользователь узнаёт правильный, увидев его. Для продуктовой гипотезы подсказка — это ответ, придуманный моделью за пользователя, и она якорит. Скил спрашивает, а не подсказывает.

## Решения

### Линзы выводятся под проект, а не берутся из учебника

Фиксированного списка линз в скиле нет. На старте сессии скил читает проект и предмет и выводит набор, обосновывая каждую линзу одной строкой применительно к этому проекту. **Линза без обоснования не предлагается** — это защита от того, чтобы скил каждый раз вываливал одинаковый список из восьми пунктов.

Набор согласуется с пользователем до первого вопроса и сохраняется в `.claude/grill-me/lenses.md` в репозитории проекта. Следующая сессия читает файл, предлагает готовый набор и дополняет его под новый предмет. Набор растёт вместе с проектом и коммитится в git.

Файл лежит в проекте пользователя, а не в `~/.claude`, — деинсталлятор его не трогает.

### Журнал и состояние — разные файлы

`journal.md` дописывается каждый раунд и к концу сессии весит десятки килобайт. `state.md` перезаписывается целиком и всегда занимает страницу.

Разделение нужно потому, что сессия заведомо переживёт компакт контекста. Восстановление не должно стоить чтения всего журнала: скил перечитывает `state.md` и продолжает с той же точки. Он же служит входом для второго прохода, где надо положить рядом решения из разных линз и найти противоречия.

### Стоп собирает документ и завершает сессию

Никакого автозавершения. Пустой фронтир, исчерпанные линзы и молчание пользователя сессию не закрывают.

Командой считаются «стоп», «хватит», «заканчиваем», «собирай документ». Не считаются «понятно», «ок», «да», «спасибо», «давай позже» и молчание. Сомнение трактуется в пользу продолжения: скил переспрашивает, а не останавливается.

Каталог сессии остаётся на диске. `/grill-me <путь к каталогу>` поднимает разговор с той же точки.

### Чистовик пишет субагент по промпту kirpr:text

Скил не может вызвать slash-команду — `/kirpr:text` запускает человек. Поэтому редактуру делает субагент, которому в промпт передаются путь к `~/.claude/kirpr/prompts/text.md`, конспект и путь для результата.

Субагент, а не оркестратор: журнал и итерации редактуры не должны оседать в основном контексте там, где он уже забит двухчасовым интервью.

Отсюда жёсткая зависимость: `grill-me` без установленного `kirpr` не соберёт чистовик. Принято осознанно — один репозиторий, один установщик.

### Три файла, а не один

`SKILL.md` держит только то, что нужно весь разговор: роутер, протокол раунда, правила остановки. `phases/lenses.md` читается один раз на старте, `phases/wrapup.md` — один раз по стопу. Протокол финальной сборки не занимает контекст все два часа сессии.

## Раскладка

```
skills/grill-me/SKILL.md              → ~/.claude/skills/grill-me/
skills/grill-me/phases/lenses.md      → ~/.claude/skills/grill-me/phases/
skills/grill-me/phases/wrapup.md      → ~/.claude/skills/grill-me/phases/
```

Правки: `install.sh`, `install-remote.sh`, `uninstall.sh` по образцу `expert-panel`; раздел в `README.md` и обновление блока «Структура проекта».

## Вызов

```
/grill-me                                    — спросит предмет
/grill-me биллинг для команд от трёх человек — свободная формулировка
/grill-me docs/hypotheses/billing.md         — файл с гипотезой
/grill-me docs/grill-me/2026-08-12-billing/  — продолжить сессию
```

Аргумент — путь к существующему каталогу сессии, значит продолжаем: читаются `state.md` и линзы, фаза 0 пропускается. Аргумента нет — скил спрашивает предмет и не начинает без ответа.

## Файлы сессии

| Файл | Кто пишет | Кто читает |
|---|---|---|
| `.claude/grill-me/lenses.md` | фаза 0 | фаза 0 следующих сессий |
| `<сессия>/journal.md` | каждый раунд, дописывание | wrap-up |
| `<сессия>/state.md` | каждый раунд, перезапись | скил после компакта контекста |
| `<сессия>/<slug>.md` | wrap-up | пользователь |

Каталог сессии по умолчанию — `docs/grill-me/YYYY-MM-DD-<slug>/`. Скил подтверждает путь при старте и без подтверждения ничего не создаёт.

## Фаза 0 — линзы

1. **Предмет.** Разобрать аргумент. Пусто — спросить.
2. **Разведка проекта.** `CLAUDE.md`, `README`, `docs/`, структура каталогов, целевой grep по терминам предмета. Задача — понять, что за продукт, а не вычитать кодовую базу.
3. **Существующие линзы.** Прочитать `.claude/grill-me/lenses.md`, если он есть.
4. **Вывод набора.** Для каждой линзы: имя, что проверяет, почему нужна именно здесь.
5. **Согласование.** Показать сохранённые отдельно от новых. Пользователь убирает лишнее и добавляет своё. Раунды не начинаются без подтверждения.
6. **Запись.** Согласованный набор — в `.claude/grill-me/lenses.md`. Новые дописываются, старые не удаляются автоматически, только по явному указанию.
7. **Путь сессии.** Предложить дефолт, дождаться подтверждения, создать каталог.

Формат линзы в файле:

```markdown
## Монетизация
Проверяет: кто платит, за что, и как цена связана с ценностью.
Добавлена: 2026-08-12, сессия «биллинг для команд».
```

## Цикл раунда

### 1. Выбор места удара

Внутри текущей линзы найти самую слабую точку и классифицировать находку. Приоритет сверху вниз:

| Тип | Что это |
|---|---|
| Нестыковка | два ответа не могут быть верны одновременно |
| Неоднозначность | ответ читается двумя способами, и от прочтения меняется продукт |
| Неизвестное | узел, без которого линзу не закрыть, а данных нет |
| Усложнение | решение сложнее задачи, которую решает |

### 2. Факты — параллельно

Вопрос упирается в факт — скил шлёт субагента и **не ждёт его**: задаёт вопрос, который от этого факта не зависит. Найденное приходит в журнал помеченным как факт со ссылкой на источник, отдельно от ответов пользователя.

### 3. Вопрос

Один. Открытый. Без гипотезы агента.

```
Линза: монетизация · раунд 12 · тип: нестыковка

❓ Как команда из трёх человек попадает на тариф, который вы описали
   как «для отделов от двадцати»?

Раунд 4: основной сегмент — маленькие команды. Раунд 9: нижний
тариф начинается с двадцати мест. Между этими двумя ответами
сегмент остаётся без продукта.
```

Тип находки и обоснование обязательны. **Вопрос, для которого скил не может назвать, что тот вскрывает, не задаётся.**

### 4. Запись

Ответ — в `journal.md`, `state.md` перезаписывается целиком. Узлы, которые открыл ответ, встают в `## Открытые узлы` в `state.md`.

## Команды пользователя по ходу

| Команда | Что делает |
|---|---|
| `не знаю` | записывается как неизвестное, не как ответ; факт добывается поиском — узел уходит в `## Ожидают факта` и ждёт субагента, нет — остаётся в `## Неизвестные` и уходит в «Открытые вопросы» |
| `пропусти` | узел уходит в `## Пропущено в этом проходе` в `state.md` и до конца прохода не поднимается |
| `линза: <имя>` | добавляет линзу на лету |
| `стоп` | запускает wrap-up |

## Проходы

Линза исчерпана — переход к следующей. Все линзы пройдены — **второй проход**: взять `state.md`, положить рядом решения из разных линз, искать, что не сходится. Вопросы второго прохода формулируются иначе: «ответ из линзы A противоречит ответу из линзы B — что из двух неверно?». Третий проход и дальше — так же.

Раунд сопоставления принадлежит линзе, чьё решение предлагается менять: заголовок сообщения и текущая линза в состоянии остаются одиночными. Линза закрыта, когда её решения сопоставлены с решениями всех остальных.

### Пустой проход

Если за целый проход по всем линзам не нашлось ни одной находки — скил говорит это прямо и предлагает три выхода: добавить линзу, дать новый вход (данные, документ, результат эксперимента) или остановиться. **Сам не завершается и вопросов ради процесса не выдумывает.**

## Wrap-up

1. **Конспект.** Оркестратор читает `journal.md` и `state.md`, раскладывает всё по структуре ниже. Состав и порядок разделов по линзам задаёт секция `## Линзы` в `state.md`: линзы проекта, исключённые из сессии, раздела не получают. Это полная фактура в нужном порядке, без редактуры.
2. **Редактура.** Субагент получает путь к `~/.claude/kirpr/prompts/text.md`, конспект и путь для результата.
3. **Ограничение субагенту: режет слова, не факты.** Ни одно число, ссылка, открытый вопрос или отброшенная формулировка из конспекта не исчезает. Информационный стиль здесь про то, как сказано, а не про то, сколько осталось.
4. **`text.md` не найден** — сказать об этом, сохранить конспект как есть, предложить прогнать `/kirpr:text` руками. Стиль по памяти не имитировать.
5. **Показать путь.** Коммит не делать.

### Структура документа

```markdown
# <Предмет>

2026-08-12 · 47 раундов · линзы: проблема, сегмент, ценность,
монетизация, метрики, риски

## Резюме
**Гипотеза.** Одна формулировка в том виде, до которого её довели.
**На чём держится.** 3–5 пунктов.
**Дыры.** 3–5 пунктов.

## Монетизация
**Решено.** ...
**Основания.** Ваш ответ (раунд 12) · факт: ARPU конкурента $18 [ссылка]
· допущение: конверсия из триала не ниже 12%
**Неизвестно.** ...

## <остальные линзы>

## Открытые вопросы
## Что развалилось по ходу
```

Резюме сверху — чтобы документ читался чужим человеком за минуту.

Раздел «Что развалилось по ходу» хранит формулировки, не пережившие прожарку, вместе с причиной. Через месяц это единственное, что удержит от возврата к уже отброшенному.

Три вида оснований — ответ пользователя, найденный факт со ссылкой, допущение — не смешиваются. Допущение, доехавшее до документа под видом факта, и есть главный способ провалить продуктовую гипотезу.

## Что скил не делает

- Не пишет код и не предлагает реализацию. Предмет — гипотеза, а не задача.
- Не делает коммитов.
- Не завершается сам.
- Не задаёт вопрос, для которого не может назвать находку.
- Не удаляет линзы из `.claude/grill-me/lenses.md` без явного указания.
