# kirpr-flow — план реализации

> **Для исполнителей:** план исполняется задача за задачей. Шаги отмечаются
> чекбоксами `- [ ]`. Шага «закоммитить» в этом плане нет и быть не может —
> см. глобальные ограничения.

**Цель:** собрать зонтичный скил `kirpr-flow` — рабочий цикл разработки от
идеи до сдачи, без единой git-операции, с обязательной верификацией в одном
из четырёх форматов и с сохранением subagent-driven development.

**Архитектура:** одна директория скила с роутером `SKILL.md`, общими
правилами в `core/`, точками входа в `modes/` и шаблонами субагентов в
`prompts/`. Роль файла определяется тем, кто его читает: режим читает
пользовательский поток управления, `core/` читают и режим и субагент,
`prompts/` режим заполняет и отдаёт субагенту.

**Стек:** markdown. Исполняемого кода в наборе нет. Правятся два
существующих bash-скрипта репозитория — `install.sh` и `uninstall.sh`.

**Спека:** `docs/kirpr-flow/specs/2026-08-13-kirpr-flow-design.md`

## Глобальные ограничения

Скопированы из спеки дословно. Требования каждой задачи включают этот
раздел.

1. **Никаких git-операций** — ни пишущих, ни читающих. Запрещены
   `git commit`, `git branch`, `git worktree`, `git merge`, `git push`,
   `git stash`, `git diff`, `git log`, `git status`, `git rev-parse` и
   чтение содержимого каталога `.git/`. Запрет распространяется на косвенные
   пути: `gh`, `jj`, MCP-инструменты вида `mcp__goland__git_status` и
   `mcp__webstorm__git_status`.
2. **Верификация обязательна.** Работа не сделана, пока не предъявлено
   доказательство одного из четырёх форматов: код → тест, скрипт → запуск,
   БД → запрос, документ → чтение целиком. Доказательство — команда и её
   вывод. Пересказ доказательством не является.
3. **Язык — русский.** Английскими остаются: имена файлов и каталогов, имена
   режимов в строке вызова, значения статусов (`DONE`,
   `DONE_WITH_CONCERNS`, `NEEDS_CONTEXT`, `BLOCKED`), уровни находок
   (`Critical`, `Important`, `Minor`) и слово `ledger` — название журнала
   работы, единое по всему набору.
4. **Только markdown.** Набор не содержит исполняемых файлов. Единственные
   правки кода в этом плане — дополнение `install.sh` и `uninstall.sh`.
5. **Пути внутри набора относительные** — к каталогу `SKILL.md`, как в
   `expert-panel` и `grill-me`.
6. **Артефакты набора** живут в `docs/kirpr-flow/specs/` и
   `docs/kirpr-flow/plans/<дата>-<тема>/`.
7. **Ни один файл набора не упоминает git иначе как запрет.** Единственное
   место с перечнем git-команд — `core/rules.md`.

## Как верифицируется задача этого плана

Почти все задачи создают markdown-файлы, поэтому формат верификации —
«документ»:

1. Прочитать созданный файл целиком, а не тот кусок, что писался последним.
2. Проверить по чеклисту: остались ли плейсхолдеры («TBD», «дополнить
   позже», «аналогично разделу выше»); есть ли внутренние противоречия; есть
   ли места с двумя прочтениями; на месте ли все разделы, перечисленные в
   задаче.
3. Записать в отчёт: команду чтения, перечень проверенных разделов и
   результат по каждому пункту чеклиста.

Задача 10 создаёт изменения в bash-скриптах — там формат «скрипт»:
верификация запуском.

Задача 12 — сквозной прогон: формат «скрипт» для grep-проверок и формат
«документ» для чтения полученных артефактов.

## Порядок задач

| № | Задача | Почему здесь |
|---|---|---|
| 1 | `core/rules.md` и `core/artifacts.md` | Фундамент: выжимка правил и форматы артефактов нужны всем остальным файлам дословно |
| 2 | `SKILL.md` | Роутер знает карту режимов; после него ясны все имена файлов |
| 3 | `core/tests.md`, `core/subagents.md`, `core/feedback.md` | Оставшееся ядро; на него ссылаются промпты |
| 4 | `prompts/implementer.md`, `prompts/task-reviewer.md`, `prompts/re-review.md` | Промпты цикла исполнения; на них ссылается `modes/execute.md` |
| 5 | `prompts/code-reviewer.md`, `prompts/spec-reviewer.md`, `prompts/plan-reviewer.md` | Промпты ревью артефактов |
| 6 | `modes/execute.md` | Центральный режим, самый большой; опирается на всё предыдущее |
| 7 | `modes/plan.md`, `modes/execute-inline.md` | Планирование и исполнение без субагентов |
| 8 | `modes/brainstorm.md`, `modes/review.md` | Вход в цикл и заказ ревью |
| 9 | `modes/debug.md`, `modes/finish.md`, `modes/skill.md` | Оставшиеся режимы |
| 10 | `install.sh`, `uninstall.sh` | Установка; верифицируется исполнением |
| 11 | `README.md` | Описание набора для пользователя |
| 12 | Приёмка | Критерии приёмки из спеки целиком |

## Источники для портирования

Оригиналы лежат в
`~/.claude/plugins/cache/claude-plugins-official/superpowers/6.3.0/skills/`.
Задачи ссылаются на них по имени скила. Портирование — это переработка на
русский с вычищенным git, а не перевод строка в строку: то, что в оригинале
держалось на коммитах и диффах, заменяется механикой из спеки.
