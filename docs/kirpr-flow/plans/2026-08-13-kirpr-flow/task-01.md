# Задача 1: core/rules.md и core/artifacts.md

Фундамент набора. Эти два файла — единственные источники правды: первый для
правил, второй для форматов. Все остальные файлы ссылаются сюда, а часть
блоков копируется из них дословно, поэтому их формулировки фиксируются
первыми.

**Файлы:**
- Создать: `skills/kirpr-flow/core/rules.md`
- Создать: `skills/kirpr-flow/core/artifacts.md`

**Интерфейсы:**
- Потребляет: ничего, это первая задача.
- Предоставляет следующим задачам:
  - блок «Выжимка для промптов» из `core/rules.md` — копируется дословно в
    начало каждого из шести файлов `prompts/*.md` (задачи 4 и 5);
  - контракт отчёта имплементера из `core/artifacts.md` — на него ссылаются
    `prompts/implementer.md` (задача 4) и `modes/execute.md` (задача 6);
  - формат строк ledger из `core/artifacts.md` — на него ссылаются
    `modes/execute.md` (задача 6) и `modes/finish.md` (задача 9).

- [ ] **Шаг 1: Создать `skills/kirpr-flow/core/rules.md`**

Файл содержит ровно шесть разделов в этом порядке.

**Раздел «Запрет git».** Перечень запрещённых команд:
`git add`, `git commit`, `git checkout`, `git branch`, `git diff`, `git log`,
`git status`, `git push`, `git pull`, `git merge`, `git stash`, `git rebase`,
`git worktree`, `git rev-parse`, `git clean`, `git init`. Отдельной строкой —
чтение содержимого каталога `.git/`. Отдельной строкой — косвенные пути:
`gh`, `jj`, MCP-инструменты вида `mcp__goland__git_status` и
`mcp__webstorm__git_status`.

Этот раздел — единственное место во всём наборе, где перечисляются
git-команды. Так устроен критерий приёмки, и задача 12 это проверяет.

**Раздел «Когда план требует коммит».** Шаг пропускается, факт уходит
строкой в ledger и в финальную сводку. Прямо запрещены подмены: архив,
копия каталога, `patch`-файл «на всякий случай» — это тот же обход другими
средствами.

**Раздел «Прямая просьба».** Если пользователь просит закоммитить, создать
ветку или слить прямо в разговоре — набор этого не делает и говорит почему:
git вне его границ. Пользователь выполняет операцию сам, а набор отдаёт ему
список изменённых файлов и сводку из `modes/finish.md`.

**Раздел «Четыре формата верификации».** Таблица:

| Что сделано | Чем доказывается |
|---|---|
| Написан код | Тест, покрывающий этот код. Допускается временный |
| Написан скрипт | Запуск скрипта |
| Изменена БД | Запрос к БД, показывающий результат |
| Написан или обновлён документ | Чтение документа целиком |

Ниже таблицы — что считается доказательством: команда и её вывод. Прямо
названы формулировки, которые доказательством не являются: «тесты зелёные»,
«должно работать», «я проверил», «выглядит корректно». Для формата
«документ» доказательство — чтение файла целиком и результат по чеклисту:
остались ли плейсхолдеры, есть ли внутренние противоречия, есть ли места с
двумя прочтениями.

**Раздел «Пятый случай».** Изменение, к которому не подходит ни один из
четырёх форматов — правка конфига, обновление зависимости, удаление мёртвого
кода. Написать «верификация неприменима» нельзя. Исполнитель обязан либо
назвать ближайший формат и то, как он его применил, либо вернуть статус
`BLOCKED`. Формулировка «неприменимо» запрещена явно, с объяснением: это
самая частая форма пропущенной проверки.

**Раздел «Выжимка для промптов».** Блок в кодовой ограде, дословно:

```
Git запрещён полностью: ни commit, ни branch, ни diff, ни log, ни status.
Если задача требует коммит — не коммить, напиши это в отчёт.
Работа не сделана, пока не предъявлено доказательство одного из четырёх
форматов: код → тест, скрипт → запуск, БД → запрос, документ → чтение целиком.
Доказательство — команда и её вывод в отчёте. Пересказ доказательством не является.
Детали: ~/.claude/skills/kirpr-flow/core/rules.md
```

Под блоком — одна строка о том, что он копируется в начало каждого
dispatch-промпта дословно, и почему дублирование намеренное: выжимка
работает, даже если субагент не открыл файл.

- [ ] **Шаг 2: Создать `skills/kirpr-flow/core/artifacts.md`**

Файл содержит четыре раздела.

**Раздел «Где что лежит».** Блок в кодовой ограде:

```
docs/kirpr-flow/specs/YYYY-MM-DD-<тема>-design.md
docs/kirpr-flow/plans/YYYY-MM-DD-<тема>/
  00-overview.md            цель, архитектура, глобальные ограничения, путь к спеке
  task-01.md … task-NN.md   задачи
  progress.md               ledger
  reports/task-NN.md        отчёты имплементеров
```

Ниже — строка о том, что ничего из этого не удаляется по завершении работы:
отчёты и ledger часть результата, а не временный мусор. И строка о том, что
набор не создаёт и не правит `.gitignore`.

**Раздел «Контракт отчёта имплементера».** Блок в кодовой ограде, дословно:

```markdown
## Статус
DONE | DONE_WITH_CONCERNS | NEEDS_CONTEXT | BLOCKED

## Файлы
Создано:  path/to/new.go — зачем он нужен
Изменено: path/to/old.go — что именно поменялось
Удалено:  path/to/dead.go — почему

## Верификация
Формат:  код | скрипт | БД | документ
Команда: <точная команда>
Вывод:   <вывод команды>

## Сомнения
```

Под блоком — почему секция «Файлы» несущая: пропущенный в ней файл ревьюер
не откроет, и изменение уедет непроверенным. Это цена отказа от диффа.
Отдельной строкой — что отчёт без секции «Файлы» или без секции
«Верификация» отклоняется до ревью.

**Раздел «Формат строк ledger».** Первая строка файла ledger:

```
# kirpr-flow ledger — план: <путь к каталогу плана>
```

Строки записей, дословно, каждая с пояснением в одну строку:

```
Задача N: готово (файлы: a.go, b.go; верификация: <команда> — <итог>; ревью чисто)
Задача N: готово (файлы: a.go, b.go; верификация: <команда> — <итог>; отложено K)
Задача N: раунд правок R/5 (устранено X, открыто Y — <находки одной строкой>)
Задача N: minor (отложено): <одна строка>
Задача N: отложено — <находка> — Решение: <почему код остаётся>
Задача N: Решение: <находка> — <что решено и почему>
```

**Раздел «Именование».** Дата в именах — по дню создания артефакта, формат
`YYYY-MM-DD`. Тема — короткий слаг латиницей через дефис. Номера задач
двузначные с ведущим нулём: `task-01.md`, а не `task-1.md`.

- [ ] **Шаг 3: Верификация — формат «документ»**

Прочитать оба файла целиком:

```
Read skills/kirpr-flow/core/rules.md
Read skills/kirpr-flow/core/artifacts.md
```

Проверить и записать результат по каждому пункту:

1. В `core/rules.md` присутствуют все шесть разделов в заданном порядке.
2. Блок «Выжимка для промптов» совпадает с текстом выше посимвольно — его
   будут копировать дословно шесть раз.
3. В `core/artifacts.md` присутствуют все четыре раздела.
4. Контракт отчёта и шесть строк ledger совпадают с текстом выше.
5. Плейсхолдеров нет: ни «TBD», ни «дополнить позже», ни «см. выше» вместо
   содержания.
6. Противоречий между двумя файлами нет: `core/rules.md` требует
   доказательство командой и выводом, `core/artifacts.md` даёт под это
   секции отчёта.

В отчёт: команды чтения, перечень проверенных разделов, результат по всем
шести пунктам.
