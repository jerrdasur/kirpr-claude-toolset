# kirpr-flow — рабочий цикл разработки без git

Зонтичный скил: восемь режимов, каждый — отдельная точка входа в свою часть
цикла, от идеи до сдачи. Режимы вызываются явно, ничего не запускается
само — без аргумента набор не угадывает, что делать.

## Разбор аргументов

Первое слово аргумента — имя режима:

| Первое слово | Файл режима |
|---|---|
| `brainstorm` | `modes/brainstorm.md` |
| `plan` | `modes/plan.md` |
| `execute` | `modes/execute.md` |
| `execute --inline` | `modes/execute-inline.md` |
| `review` | `modes/review.md` |
| `debug` | `modes/debug.md` |
| `finish` | `modes/finish.md` |
| `skill` | `modes/skill.md` |

- Первое слово совпало с именем режима — читай соответствующий файл и следуй
  ему. Остаток строки — аргумент режима.
- Первое слово не распознано — спроси, какой режим нужен. Не угадывай.
- Аргументов нет — спроси, что делаем. Не угадывай по содержимому
  репозитория.
- Аргумент похож на путь, но по нему ничего нет — скажи это и спроси, что
  имелось в виду. Предметом такой аргумент не становится.

Пути к `core/*.md`, `modes/*.md` и `prompts/*.md` — относительно каталога
этого файла.

## Инвариант

Три пункта, действующие во всех режимах:

1. Git запрещён полностью — ни пишущих операций, ни читающих. Полный
   перечень в `core/rules.md`.
2. Верификация обязательна: код → тест, скрипт → запуск, БД → запрос,
   документ → чтение целиком. Доказательство — команда и её вывод.
3. Артефакты лежат по путям из `core/artifacts.md`.

## Карта файлов

- `core/` — общие правила. Читают и режим, и субагент, которого режим
  запускает: `core/rules.md` — запрет и форматы верификации,
  `core/artifacts.md` — пути артефактов и форматы отчёта и ledger.
- `modes/` — точки входа. Каждый файл читает только сам режим, в который
  ведёт таблица выше; субагенту он не передаётся.
- `prompts/` — шаблоны для субагентов. Режим заполняет шаблон конкретной
  задачей и отдаёт получившийся текст субагенту как промпт.
