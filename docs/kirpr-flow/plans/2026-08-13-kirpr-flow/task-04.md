# Задача 4: промпты цикла исполнения

Три шаблона, которыми `modes/execute.md` запускает субагентов внутри цикла
задачи.

**Файлы:**
- Создать: `skills/kirpr-flow/prompts/implementer.md`
- Создать: `skills/kirpr-flow/prompts/task-reviewer.md`
- Создать: `skills/kirpr-flow/prompts/re-review.md`

**Интерфейсы:**
- Потребляет: блок «Выжимка для промптов» из `core/rules.md` (задача 1) —
  копируется дословно в начало каждого из трёх файлов; контракт отчёта из
  `core/artifacts.md` (задача 1); `core/tests.md` и `core/feedback.md`
  (задача 3) — по ссылке.
- Предоставляет: `modes/execute.md` (задача 6) заполняет эти шаблоны.
  Имена подстановок, перечисленные ниже, задача 6 обязана использовать
  дословно.

**Источник для портирования:** `implementer-prompt.md`,
`task-reviewer-prompt.md` и `re-review-prompt.md` скила
`subagent-driven-development` из
`~/.claude/plugins/cache/claude-plugins-official/superpowers/6.3.0/skills/`.

- [ ] **Шаг 1: Создать `skills/kirpr-flow/prompts/implementer.md`**

Файл открывается блоком выжимки правил из `core/rules.md`, скопированным
посимвольно. Дальше — тело шаблона с подстановками
`{МЕСТО_В_ПРОЕКТЕ}`, `{ПУТЬ_К_ЗАДАЧЕ}`, `{ПУТЬ_К_ОТЧЁТУ}`,
`{ИНТЕРФЕЙСЫ}`, `{ГЛОБАЛЬНЫЕ_ОГРАНИЧЕНИЯ}`.

Тело содержит:

**«Что читать первым».** `{ПУТЬ_К_ЗАДАЧЕ}` — это требования. Читать целиком.
Все точные значения — числа, строки, сигнатуры, имена файлов — брать оттуда
дословно, не по памяти и не по смыслу.

**«Порядок работы».** Прочитать задачу. Задать вопросы, если что-то неясно,
до начала работы. Написать тест (см. `core/tests.md`). Убедиться, что он
падает. Реализовать. Убедиться, что тест проходит. Самопроверка: перечитать
задачу и сверить сделанное по пунктам. Написать отчёт в `{ПУТЬ_К_ОТЧЁТУ}`.

**«Границы правок».** Два правила, которых нет в оригинале и которые следуют
из отсутствия отката:

- не трогать файлы вне списка из задачи; если работа требует правки за его
  пределами — вернуть `NEEDS_CONTEXT` и назвать файл;
- не переписывать файл целиком там, где хватает точечной правки.

Под правилами — одна строка почему: в этом наборе нет коммитов, поэтому
испорченный файл не возвращается штатными средствами.

**«Ты не запускаешь субагентов».** Ни помощников, ни ревьюера. Ревью придёт
от контроллера после отчёта.

**«Контракт отчёта».** Блок отчёта из `core/artifacts.md`, скопированный
дословно. Ниже — что возвращать в ответе контроллеру: только статус, список
затронутых файлов, одну строку про верификацию и сомнения. Полный текст
живёт в файле отчёта, а не в ответе.

**«Статусы».** Расшифровка всех четырёх: `DONE`, `DONE_WITH_CONCERNS`,
`NEEDS_CONTEXT`, `BLOCKED` — по одной строке, когда какой уместен.

- [ ] **Шаг 2: Создать `skills/kirpr-flow/prompts/task-reviewer.md`**

Файл открывается тем же блоком выжимки правил. Подстановки:
`{ПУТЬ_К_ЗАДАЧЕ}`, `{ПУТЬ_К_ОТЧЁТУ}`, `{ПУТЬ_К_OVERVIEW}`,
`{СПИСОК_ФАЙЛОВ}`.

Тело содержит:

**«Что ты получаешь».** Четыре пути. `{СПИСОК_ФАЙЛОВ}` — файлы, которых
коснулась задача, по секции «Файлы» отчёта.

**«Как читать».** Файлы из списка читаются целиком, а не выборочно и не
кусками вокруг предполагаемых правок. Диффа нет — полный текст файла и есть
предмет ревью.

**«Два вердикта».** Отчёт обязан содержать оба, иначе он не принимается:

1. Соответствие задаче: что требовалось, что сделано, что сделано сверх
   требований.
2. Качество: находки с уровнями `Critical`, `Important`, `Minor`.

**«Правило бойскаута».** Ты видишь старый код рядом с новым — это
нормально, отмечай найденное. Граница: находки в файлах из
`{СПИСОК_ФАЙЛОВ}` идут в отчёт как обычные находки; всё за их пределами
помечай отдельно как «вне границы задачи» — контроллер решит, что с этим
делать.

**«Чего не делать».** Не перезапускать тесты, которые уже прогнал
имплементер, — доказательство в отчёте. Не менять файлы: ревью только
читает. Не выносить вердикт «готово к слиянию» — слияниями набор не
занимается.

**«Что отметить особо».** Пункты, которые не проверяются из предоставленного
— требования, живущие в файлах, которых задача не касалась. Их надо назвать
явно; они не блокируют ревью, их разрешает контроллер.

- [ ] **Шаг 3: Создать `skills/kirpr-flow/prompts/re-review.md`**

Файл открывается тем же блоком выжимки правил. Подстановки:
`{СПИСОК_НАХОДОК}`, `{ПУТЬ_К_ЗАДАЧЕ}`, `{ПУТЬ_К_ОТЧЁТУ}`,
`{ФАЙЛЫ_ЭТОГО_РАУНДА}`.

Тело содержит:

**«Твоя область».** Только находки из `{СПИСОК_НАХОДОК}` и только файлы из
`{ФАЙЛЫ_ЭТОГО_РАУНДА}`. Это узкое ревью, а не повторение полного.

**«Вердикт по каждой находке».** Ровно одно из двух: «устранено» с указанием
файла и строки, или «не устранено» с объяснением, чего не хватает.
Промежуточных формулировок нет.

**«Новые поломки».** Отмечать только то, что сломано правками этого раунда.
Новые `Critical` и `Important` присоединяются к списку открытых находок.

**«Наблюдения не по теме».** Всё, что не входит в область, идёт отдельным
списком «вне области» — контроллер отправит это в ledger отложенным. Такие
наблюдения цикл правок не продлевают.

- [ ] **Шаг 4: Верификация — формат «документ»**

Прочитать все три файла целиком:

```
Read skills/kirpr-flow/prompts/implementer.md
Read skills/kirpr-flow/prompts/task-reviewer.md
Read skills/kirpr-flow/prompts/re-review.md
```

Проверить и записать результат по каждому пункту:

1. Каждый из трёх файлов начинается с блока выжимки правил, и текст блока
   посимвольно совпадает с `core/rules.md`. Сверять чтением обоих файлов, а
   не по памяти.
2. Все подстановки перечислены в файле явно и записаны в том же виде, что в
   этой задаче: `{ПУТЬ_К_ЗАДАЧЕ}`, `{ПУТЬ_К_ОТЧЁТУ}`, `{ПУТЬ_К_OVERVIEW}`,
   `{СПИСОК_ФАЙЛОВ}`, `{МЕСТО_В_ПРОЕКТЕ}`, `{ИНТЕРФЕЙСЫ}`,
   `{ГЛОБАЛЬНЫЕ_ОГРАНИЧЕНИЯ}`, `{СПИСОК_НАХОДОК}`, `{ФАЙЛЫ_ЭТОГО_РАУНДА}`.
3. В `implementer.md` контракт отчёта совпадает с `core/artifacts.md`.
4. Слово `git` встречается только внутри блока выжимки правил и нигде больше.
5. Плейсхолдеров нет — подстановки в фигурных скобках плейсхолдерами не
   считаются, это часть шаблона.
6. Противоречий между шаблонами нет: имплементер обязан дать доказательство,
   ревьюер обязан не перезапускать уже прогнанное.

В отчёт: команды чтения, перечень проверенных разделов, результат по всем
шести пунктам.
